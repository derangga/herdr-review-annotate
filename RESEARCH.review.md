# Review of RESEARCH.md

Reviewed on 2026-10-04 against the installed `herdr 0.9.1`, the three cloned repos, and the Herdr docs
at tags `v0.9.1` and `v0.9.3`. Nothing was built. No pane was opened and no prompt was sent, so every
claim that needs a live pane is marked unverified.

Evidence shorthand: `annotate/` is `herdr-annotate/rust/src/`, `plugins.mdx` and `socket-api.mdx` are the
doc files at `https://raw.githubusercontent.com/herdrdev/herdr/v0.9.3/docs/next/website/src/content/docs/`.

## Blockers

| # | Where (section) | Problem | Evidence | Suggested fix |
|---|---|---|---|---|
| B1 | 4.7, 4.8, 9 | The `startup` hook cannot supply `binary-path` when the agent needs it. Startup hooks run only after a server start or a live handoff. After `plugin install`, `plugin link` or `plugin enable` the file does not exist until the Herdr server restarts, and the server is persistent. | `plugins.mdx`, "Startup hooks": "They run again when a new server takes over during live handoff, but not when a client attaches, config reloads, or a plugin is linked or enabled." This also answers the second "Still open" item. | Delete the `startup` subcommand and the `[[startup]]` entry. The skill reads the root from Herdr: `herdr plugin list --plugin review --json` returns `plugin_root` (verified on `annotate`, the field holds `/nix/store/...-herdr-annotate-0.5.0`). This also survives the plugin moving, which a file written once does not. |
| B2 | 1, 4.2, 6, 7 | The store that sections 4.2 and 6 say to reuse has no `flock` and no torn-write handling. It uses a `mkdir` lock directory that fails at once with "busy; try again", treats a lock as stale only after 30 seconds, and rejects the whole file when one line does not parse. Reused as written, an agent CLI call that overlaps a TUI write returns an error, and one torn line makes the review unreadable. | `annotate/store.rs:305-340` (lock directory, no retry), `:20` and `:354-360` (30 s stale rule), `:253-256` (any bad line fails the load), `:262-292` (updates rewrite the file through a temp file and `rename`, the opposite of append-only). `Cargo.toml` enables `rustix` with the `process` feature only. | Do not copy `store.rs`. Take the lock with `std::fs::File::lock` (stable since Rust 1.89, the toolchain here is 1.98.1), which the kernel releases when a writer dies. Build each record as one `String` ending in `\n` and write it with a single `write_all` on an `O_APPEND` handle. The reader skips a final line with no newline and skips unparseable lines with a warning. |
| B3 | 4.6, 4.7 | Targets are stored as public pane ids (`REVIEW_DELIVER_TO`, `meta.json`, `$HERDR_PANE_ID` in agent-initiated `open`). Public pane ids are not stable. A stale id fails the send, or addresses a different pane and delivers the comments to the wrong agent. | This session has `HERDR_PANE_ID=w8D:p2`, yet `herdr pane get w8D:p2` returns `pane_not_found` and `herdr pane list` shows one pane, `w8D:p1`. Cause unverified. `socket-api.mdx` line 290: "Cross-workspace moves keep the internal pane and terminal alive but assign a new public pane id." `herdr agent get term_65cfeec9f35116` returns `agent_not_found`, so `terminal_id` is not accepted as a target. | Store `terminal_id` next to the pane id. Before every send, run `agent get` and require the same `terminal_id` and a `cwd` inside the review root. On mismatch, fall through to `agent list` and match by `terminal_id`, then by `cwd`. Agent-initiated `open` must resolve its own pane the same way instead of trusting `$HERDR_PANE_ID`. |
| B4 | 4.3, 4.5, 9 (decisions 4, 10) | Comments have nowhere to render once their file leaves the diff, and each diff spec hides half of the loop. In the working-tree spec a commit empties the diff, so every comment loses its file. In `base...HEAD` an uncommitted fix never appears, so the user cannot see what the agent changed. Decision 10 says outdated comments stay visible, but 4.5 only draws cards under diff lines. | `git diff A...B` compares the merge base with `B` and ignores the working tree (git-diff documentation). Section 4.5: "Comment cards render under the line." | Add one "comments not in this diff (N)" block at the top of the stream. Keep decision 4's two specs, but compute the branch spec as `git diff $(git merge-base <base> HEAD)` so it includes uncommitted work. |

## Design gaps

| # | Where | Gap | Failure scenario | Suggested fix |
|---|---|---|---|---|
| G1 | 4.6, 7 | No resend. Section 7 says reopening is the only way back, but only a resolved comment can be reopened. | The user sends three comments to a working agent, then presses Esc, or the agent restarts. The comments are `sent` and open, and no key sends them again. | Make `S` on a focused comment resend it, or add `send --all-open`. One flag, no new state. |
| G2 | 4.2, 4.3 | The anchor is underspecified and the hash adds nothing. The design stores the line text anyway, to show it on outdated comments. A hash that includes context goes stale when a neighbouring line changes. Only lines inside hunks can be searched. | The agent edits the line above a comment. The hash changes and the comment is tagged outdated although its line is untouched. | Store the line text only. A comment matches when the same path, side and line hold the same text. Otherwise search the file's diff rows for the nearest identical line. Otherwise it is outdated. |
| G3 | 4.5, decision 10 | Every successful fix makes its comment outdated, because the fix changes the anchored line. | After one round the screen shows an `outdated` tag on every comment the agent handled. | Show the tag on open comments only. An open, outdated comment then means "changed but not resolved", which is worth seeing. Resolved comments are already collapsed. |
| G4 | 4.2 | Decision 7 moves resolved comments to `archive.jsonl`, which rewrites `review.jsonl`. Section 4.2 says writers "never rewrite each other", and also lists `archive` as an event. | An agent appends while the TUI archives. The append lands in the old inode after the rename and is lost. | Archive under the same lock every append takes, and reopen the file after taking the lock. Decision 7 stays feasible. |
| G5 | 4.2 | Event order is never defined. | Two readers that sort by the `at` timestamp disagree after clock skew or equal timestamps. | State that file order is the only order. `at` is display data. |
| G6 | 4.2 | Short ids have 16 bits. | Collision odds reach about 50% near 300 comments, inside the document's "hundreds of comments". The agent resolves the wrong comment. | Allocate a counter under the lock (`u1`, `a1`). It is shorter and cannot collide. |
| G7 | 4.1, 4.7 | Behaviour for a wrong id is undefined. | The agent mistypes an id. A silent success hides it. | Exit non-zero and print the open ids. |
| G8 | 4.6 | The prompt tells the agent to pass reply text in double quotes. | The agent runs `comment reply u-1 "Used `with_capacity`"`. The shell executes the backticks, and `$(...)` likewise. | Read the reply from stdin with a quoted heredoc, or instruct single quotes. Merge the two commands into `comment resolve <id> --reply -`, which also halves the agent's tool calls. |
| G9 | 4.6 | The absolute path is unquoted in the prompt. | A linked plugin under a path with a space produces a broken command. | Shell-quote the path when formatting. |
| G10 | 4.2, 4.6 | Status is per comment, but threads are resolved as a unit. Reopened comments have no prompt format. | The user reopens with no new text. The agent receives the same line again and nothing says its fix was rejected. | Status lives on the root comment and replies have none. A reopened root is sent with its thread and a "reopened" marker. |
| G11 | 4.2 | The review key is "root plus a diff spec", the directory is `hash(root)` only, and the defaults say "keyed by repo or worktree root". | The user switches from the working-tree spec to the branch spec. Old-side line numbers now refer to a different base, so anchors point at the wrong lines. | Key by root only and store the spec in each comment's anchor. Say so in 4.2. |
| G12 | 4.6 | Resolution step 3 keeps agents whose `cwd` is inside the review root. | In this directory the agent's `cwd` is the parent of `hunk/`, `zeron/` and `herdr-annotate/` (`herdr agent list`), so no repo matches and send refuses. | Also accept an agent whose `cwd` is an ancestor of the root when it is the only agent in the workspace. |
| G13 | 4.7 | `open` has no rule for a pane that is already open. | The skill tells the agent to run `open` after each batch, so each run adds another split. | Record the review pane's id in `meta.json`. `open` calls `herdr plugin pane focus <id>` when that pane still exists. |
| G14 | 4.3 | The git invocation ignores user config and edge cases. Paths are quoted by `core.quotePath`. `diff.noprefix` and `diff.mnemonicPrefix` change headers. `textconv` rewrites content. A repo with no commits has no `HEAD`. Untracked files need a synthesized patch and a size check before reading. `origin/HEAD` is often unset, and a base equal to `HEAD` gives an empty diff. Submodules, CRLF and delete-then-recreate are not mentioned. | A file named with non-ASCII characters appears as `"\303\251.rs"` and never matches a comment path. A 2 GB untracked artifact is read into memory. | Run `git -c core.quotePath=false diff --no-color --no-ext-diff --no-textconv --src-prefix=a/ --dst-prefix=b/ -M`. Take paths from the `---`, `+++` and `rename` lines. Stat untracked files before reading. Show a message for no commits, a missing base, and an empty diff. Strip `\r` before comparing anchors. Show submodules as a one-line entry. |
| G15 | 4.3 | Watching the worktree recursively with `notify`. | On Linux, inotify needs one watch per directory. A repo with `node_modules` or `target` hits the watch limit. The diff also reloads on every build artifact write. | See the cut list. Reload when `review.jsonl` changes and on `r`. |
| G16 | 4.3, 4.5 | A reload while the user is typing a comment is not addressed. | The agent edits a file while the editor is open. The rows shift under the cursor and the comment saves against the wrong line. | Freeze the diff while the editor is open and capture the anchor when `c` is pressed. |
| G17 | 4.6 | `sent` is appended after the prompt is accepted, and the two steps are not atomic. | The TUI dies between them, and the next send repeats the batch. | Accept it as at-least-once delivery and say so in section 7. |
| G18 | 7 | The text sanitizer exists but is missing from the reuse table. ESC stripping alone is not enough for rendering. | Agent text containing `\r` or C0 controls redraws over the UI. | Reuse `sanitize_terminal_text` (`annotate/format.rs:7-21`) for every comment body and every diff line. |
| G19 | 4.2, 7 | The agent CLI writes outside the workspace, in `$XDG_STATE_HOME`. | A sandboxed agent cannot write there, so reply and resolve fail. Unverified for Codex, which decision 16 defers. | Record it as a risk for the Codex pass. Use one rule on both systems, `${XDG_STATE_HOME:-~/.local/state}`, and drop the macOS branch. |
| G20 | 4.2 | Nothing stops an agent resolving a comment it did not fix. No automatic loop exists, because the agent acts only after the user sends. | The agent resolves ten comments without changes, and the user must open each one. | Require a reply with every agent resolve (see G8). The `new` marker then always has text beside it. |

## Smaller issues

- 4.3 and 4.5: `r` is both "reload" and "reply".
- 4.5: no key for editing or deleting your own comment, although 4.2 grants both. `e` is taken by archive.
- 4.1: the table says agents may "edit only their own comments", but the subcommand list has no `edit`.
- 4.1 and 4.2: archive has two names, the `archive` subcommand and `comment clear --resolved`. In hunk, `clear` deletes.
- 8: milestone 6 lists `comment add|apply|list|reply|resolve|reopen` and omits `rm`, `clear`, `context`, `files` and `skill` from the 4.1 table.
- 4.2: the state diagram has no agent-authored comment (which is never `sent`) and no agent reopen.
- 4.8: the manifest sets `min_herdr_version = "0.9.1"` while section 3 cites 0.9.3 docs. Say which version is the target.
- 4.8: the list of keys `herdr-annotate` uses is incomplete. Its README also binds `prefix+shift+a`, `prefix+ctrl+a`, `prefix+ctrl+v`, `prefix+ctrl+s`, `prefix+shift+o`, `prefix+ctrl+o` and `prefix+t`.
- 4.6: the status line `Send 3 unsent > claude in w1:p2` needs a resolved target on every redraw. Cache it and refresh it on send.
- 4.6: a reply line quotes agent text back into the prompt. That is harmless with one agent and becomes an injection path with the reviewer agent in milestone 8.
- 5: "offsets into one `String`" and "windowed render" are optimizations with no measurement behind them. Build the simple version and measure.
- 6: `editor.rs` is not a drop-in. It imports `store`, `types`, `layout`, `termination`, `paths` and `format` (`annotate/editor.rs:16-26`).
- 8: only milestones 1 and 2 state a check. Milestones 3 to 8 need one each. For milestone 5, a comment sent to an idle Claude Code produces a reply and a resolve in the TUI with no typing.
- 8: the riskiest unknowns are tested late (send to a working agent, `--env`, pane id stability). Move a spike into milestone 1 that sends a fixed prompt with `herdr agent prompt` and prints the pane's environment.
- 8: "the first useful version is the end of 5 plus reply and resolve" also needs the store reload from milestone 6, or the user never sees the reply.
- Missing for the first week: error and exit-code rules for the CLI, a log location (`herdr plugin log list` covers actions only, not the pane or the agent CLI), a config file format for the placement setting in 4.5, a test plan beyond parser fixtures, CI, and release.
- Missing install flow for this machine. The plugin is linked from a Nix store path (`herdr plugin list` shows `local:/nix/store/...`), and `plugin link` skips `[[build]]`, so the fetch script never runs here.
- 7: "the design has no Unix-only dependency except the optional file lock and `rustix`" is moot with `std::fs::File::lock`.

## Verdict

Milestone 1 can start, because the skeleton and the `open` action depend on none of the blockers. Before milestone 4, replace the storage plan (B2) and decide where comments go when their file leaves the diff (B4). Before milestone 5, drop the startup hook (B1), stop trusting stored pane ids (B3), add resend (G1), and pick keys that do not shadow Herdr's defaults (W3).
