# Tests that the graphs give

Part of the [herdr-review design](../DESIGN.md).

Each `E:` line above is one test, and each test swaps only the parameters listed under `R:`.

| Graph | Swapped | Tests |
|---|---|---|
| Store write | temp `dir`, fixed `now` | Lock held by another process gives `Busy` after 2 s. A killed holder frees the lock. `build` returning an error writes nothing |
| Archive | temp `dir`, fixed `now` | A held lock gives `Busy` and changes neither file. A bad line stays. Nothing to archive writes nothing. An archive that cannot be appended to and a rename that fails each leave the log as it was. Other processes appending beside it lose nothing and get no id twice |
| Agent CLI | fixture `git`, recording `herdr`, temp `dir` | Unknown id, a second `resolve` is a no-op, a line past the end of the file, an oversized body, a `herdr` failure does not fail the command |
| `open` | recording `herdr`, `Env` literal | No context JSON, review pane already open, stale review pane, no agent |
| Load diff | fixture `git` | Every row of the cases in `diff.md`, and a failed reload keeps the old diff |
| TUI loop | `TestBackend`, key list, temp `dir` | A write from another process appears, a failed save keeps the editor text, termination with a draft saves it |
| Filter the files | `TestBackend`, key list | Every `E:` line of the graph, each decision of `filter` in `tui.md`, and `matches` and `sidebar_rows` directly. The fixture is a diff of four files in two directories |
| Changed words | `TestBackend`, a patch of one hunk | `changed` directly: the tokens, a renamed identifier, tokens added to one line, neighbours joined, an indent, the half-shared rule at and under the line, the 200 token limit, a repeated token. Drawn: the marks in the unified and the split layout, a rewritten line and a line with no partner have none, the cursor's row and a selected row keep them, the marks follow the sideways scroll |
| Collapse | `TestBackend`, key list, temp `dir` | The key from inside a file and again on the header, the file chosen in the sidebar, the header's counts and their plurals, a thread jump forward from the header and backward from the file below, backward from the header itself, a file comment on a collapsed header, a reload, a hunk jump, visual mode, no file under the cursor, a collapsed file is not read for colours |
| Viewed | `TestBackend`, key list, temp `dir` | The key from inside a file and again on the header, the file chosen in the sidebar, the sidebar `✓` and the unsent `•` over it, the header's word, the status count, a new pane starts a viewed file collapsed, a changed file loses the mark and opens, a file that left the diff leaves `meta.json`, `collapse` on a viewed file keeps the mark, no file under the cursor, a save that fails warns. `fingerprint` directly: context rows and line numbers do not count, an added row does |
| Whole file | fixture `git`, temp repo dir, key list | `fill` directly: the lines between, above and below the hunks, their old numbers, the headers, a row that reads differently, a file shorter than its hunks, a hunk with no new row. Through the key: a modified file, an added file, a collapsed file opens, the cursor keeps its line, the key again, a reload keeps it, a file over 1 MiB, a comment on a filled line is matched |
| Highlight | recording `git`, temp repo dir, a budget that counts lines | A side that cannot be read falls back to its hunks, so does one over 1 MiB, an unknown extension reads nothing, steps of 50 lines add up to the tokens of one whole pass, the loop reads no file while keys are waiting |
| `state` and `file` | fixture `git`, temp `dir`, a temp repo for the read-only test | Every `E:` line of `graphs/json.md`. The read-only test: `review.jsonl`, `meta.json`, the work tree and `.git/index` are byte-identical after both commands, and no store directory appears. Golden output against `herdr-app-mod/test/fixtures/state.json` and `file.json` (`REVIEW_UPDATE_FIXTURES=1` rewrites them). The read-only test runs the real binary over a real repository, in `tests/state_readonly.rs`. A thread placed `not_in_diff` is an orphan and in no file's counts. `viewed` follows the fingerprint. Tokens: UTF-16 offsets on a non-ASCII row, none for an unknown language, a line budget, a build without `syntax` (its own test, since the golden `file.json` has tokens) |
| User CLI | fixture `git`, recording `herdr` and `hc`, temp `dir`, temp body files | `--as user` writes `by: user` and calls neither `herdr` nor `hc`. A body file is read and deleted, also when the body is too long, and one that cannot be deleted is still read. A symlink and a directory are refused and left alone. An agent's `reply` refuses `--body-file`. `edit` and `delete` of an agent's comment give `NotAllowed`. `seen` of a thread that is not new writes nothing. `resolve` of a resolved thread and `reopen` of an open one write nothing. `apply --spec branch --base B` anchors under that spec. An old-side anchor on a renamed file reads `old_path`. `archive` with nothing to move writes nothing and prints zeros. `view --set` of a file not in the diff gives exit 2, `--unset` of an unmarked path writes nothing. The three `unknown ...` usage messages stay as written |
| Send under hc | recording `hc`, temp `dir`, `Env` literal | Every `E:` line of the hc part of `graphs/send.md`. Each refusal by `hc get` (finished, not found, no status, blocked) and by `hc send` (exit 9, 11, 3, another). A stored address that is gone or has another folder falls to the list. `--target` skips the folder check. `Ambiguous` lists the candidates, and `--json` prints them. `--thread` sends a sent thread and only the named ones, and an id that is not open is exit 2 under both backends. `<bin>` is `current_exe`. `--json` has one test per `error` kind and a success, queued and nothing-to-send object, also under herdr. The backend is the flag, else `--target` or `HC_TERMINAL_ID`, else herdr. Under hc `send` calls no herdr and notifies nothing. The text has no ESC. `sent` not recorded still reports success. The agent name comes from `hc get` and a failed call gives a plain `agent` |
| `meta.json` under two binaries | temp `dir` | A file with both `target` and `hc_target` loads with the v0.5.0 `Meta` shape (a copy of that struct in the test) and keeps `target`. Saving `hc_target` leaves `target`, `viewed` and `spec` as they were |
| GUI decode | none, fixtures only | `decodeState`, `decodeFile`, `decodeSend` and `decodeProps` on the golden files, on a wrong `schema`, on a missing and a retyped field, on `null` where a value is expected |
| GUI update | none, a list of `Msg` | Every row of the E table in `gui.md` through `failed`. Single flight: a burst of triggers, a trigger with the editor open, a stale `Loaded`, `pending` after a failure. The exhaustive switch |
| GUI rows | none | The layout of rows and cards, a card under its `row`, an outdated card, an orphan list. Selection to anchor: one row, a range, the first side kept across `del` and `add`, a hunk row ignored, an old-side range on a renamed file |
| GUI graphs (open, load, comment, thread, send, archive and viewed) | `FakeHost` | Every `E:` line of `graphs/gui-*.md`, and the argv of each CLI call. The body never on argv. `exec` is called as often as the graph says |
| Send under herdr | recording `herdr`, temp `dir` | Each `Refusal`, a stale pane id falls through to the list, `Ambiguous`, `sent` not recorded still reports success |

If a test needs a real `git`, a real Herdr, a real `hc`, a real herdr-app or a real terminal to exercise one of these graphs, the
function has a hidden dependency and the design is wrong. The temporary-repository tests of the diff engine
and of the read-only test of `state` and `file`, and the manual checks in `message-review.md`, are the only places
that use the real tools, and they test the tools' behaviour, not our graphs.

The mod's tests run with `node --experimental-strip-types --test 'test/*.test.ts'` in `herdr-app-mod/`. The
GPUI `view` has no unit test. A bead that changes it runs `herdr-app check` on the staged mod and looks at a
`herdr-app shot` of the running app, and says in its close note what it looked at.
